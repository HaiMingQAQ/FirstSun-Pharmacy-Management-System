# FirstSun V2 现代化 UI 升级 AI 执行提示词

## 使用方法

将下面代码块中的内容完整复制给负责实施 UI 升级的 AI。第一轮只执行公共 UI 基础和两个 V0 样板页；V0 截图确认后，再让 AI 继续批量迁移其他页面。

```text
你正在协助我升级 FirstSun 药店管理系统管理端 UI。项目根目录为：
D:\github-2\FirstSun Pharmacy Management System

V2 原型参考目录为：
E:\github\xmlg-2\2-资料2\小型药店管理系统界面原型V2

如果上述 V2 路径不存在，请在 E:\github\xmlg-2 下搜索同名目录并报告实际路径，不要跳过原型分析，也不要凭空设计。

本次目标：以 V2 原型的信息架构、药店业务语义和主要页面布局为参考，在现有 yudao Vue3 + Element Plus 管理端内完成现代化升级。不是复制静态 HTML，也不是另建一套前端。必须保留现有登录、动态菜单、路由、多页签、权限指令、字典、分页、上传组件、真实 API 和业务校验。

开始前必须阅读：
1. docs/V2现代化UI风格规范-初版.md
2. docs/前端界面统一规范.md
3. docs/开发规范与AI协作规则.md
4. docs/团队开发须知.md
5. .trae/documents/pharmacy-base-ui-simplification.md

当前分支应为 A-base。先执行 git branch --show-current、git status --short、git log -1 --oneline 并报告结果。工作区可能已有他人修改，不得覆盖、回滚、格式化或删除任何非本次变更；不得使用 git reset --hard、git checkout --、git clean。未经我明确要求，不提交、不合并、不推送 Git。

本轮范围只包含：
1. 现状和原型审计。
2. 药店管理端公共视觉基础。
3. FirstSun 系统外壳的受控现代化调整。
4. 药店工作台首页 V0。
5. 药品档案列表及表单 V0。
6. 必要的规范文档更新和浏览器验收记录。

本轮禁止：
1. 批量改造 B～F 的所有业务页面。
2. 改后端 Java、数据库表、既有 API 语义、权限标识和字典值。
3. 引入新的 UI 框架、图表框架或重量级依赖。
4. 使用 Mock 数据或静态随机数字冒充真实接口完成。
5. 为追求视觉效果删除查询、分页、审核、删除、权限控制等已有功能。
6. 大面积使用渐变、玻璃拟态、超大圆角、装饰性圆球、营销页 Hero 或卡片嵌套卡片。
7. 在未看源码前假定布局文件、路由文件或样式入口的位置。

统一设计方向：
- 产品定位：现代、可信、清晰的药店运营工作台，不是通用后台演示站。
- 品牌主色：#176B5B；交互强调色：#16A085。
- 页面背景：#F5F7F8；面板背景：#FFFFFF。
- 主文字：#1F2933；次级文字：#667085；边框：#E4E7EC。
- 使用 Element Plus 语义色表达成功、警告、危险和信息状态。
- 圆角以 6px/8px 为主；轻边框、弱阴影；间距采用 4px/8px 基础体系。
- 默认以浅色主题作为视觉验收标准，现有深色切换不得因本次修改崩坏。
- 字体沿用项目系统字体栈，不新增网络字体，不使用随视口缩放的字体。
- 图标优先复用项目现有 Icon/Element Plus 图标，禁止用 emoji 充当正式功能图标。

实施步骤：

第一步：审计，不改代码。
- 阅读 admin-ui 的 package.json、样式入口、主题变量、layout、Logo、侧边菜单、顶部导航、多页签、首页路由和 pharmacy 页面。
- 对照 V2 原型，整理“保留的信息架构、需要现代化的视觉、不能照搬的静态实现”。
- 检查是否存在正式 FirstSun Logo。若没有正式 Logo，保留现有资产作为临时占位并明确报告，不得自行生成或伪造品牌 Logo。
- 启动条件允许时，保存修改前的首页、药品档案列表和表单截图到临时 QA 目录，不得加入 Git。
- 输出将修改的文件清单、每个文件的必要性、风险和回退点，然后再开始编辑。

第二步：建立公共视觉基础。
- 优先通过 CSS/SCSS 变量和受控作用域建立药店设计令牌，不把颜色散落到各页面。
- 新增公共样式前先确认项目现有样式结构。建议目录为 admin-ui/src/styles/pharmacy，但如果项目已有更合适的约定，应遵循现有约定。
- 只有至少两个页面真正重复时才提取公共组件，禁止为了“架构完整”创建空壳组件。
- 公共样式不得破坏 system、bpm、mall 等非药店模块。

第三步：升级系统外壳。
- 保留 yudao 的动态菜单、权限、折叠、顶部工具、路由和多页签机制。
- 将明显的 yudao 演示品牌视觉替换为 FirstSun 药店管理语义，但不得删除仍在使用的框架能力。
- 调整侧边栏、顶部栏、标签页、页面背景、内容容器、选中态和悬停态。
- 侧边栏应稳定、安静、便于扫描；不要把每个菜单做成独立卡片。
- 系统名称和品牌必须在首屏清晰可见；没有正式 Logo 时不得假装已经完成品牌资产。

第四步：制作两个 V0 样板。
- 工作台首页 V0：移除 yudao 项目宣传卡片和无关演示内容，改为药店业务工作台结构。
- 首页可以展示真实接口已有的数据；没有接口的模块使用规范空状态或“暂无数据”，不得编造经营数据。
- 药品档案 V0：在已经完成的查询区、表格和抽屉表单基础上统一视觉，不得回退已有功能。
- 简单 CRUD 的后续参考页是药品分类；复杂表单参考页是药品档案。
- V0 完成后停止扩展，提供 1440px 和 1024px 截图，等待我确认后再批量迁移。

页面实施规则：
- 高频查询直接展示，低频条件放“更多筛选”。
- 主操作直接显示，低频行操作放“更多”下拉并保持原权限判断。
- 简单表单使用 Dialog；字段多或需要分组的表单使用 el-drawer + 连续分区，不用 Tabs 隐藏校验错误。
- 表格首列优先放业务识别字段，操作列固定右侧；金额、数量、状态对齐一致。
- 状态优先使用 dict-tag 和既有字典；审核状态与启停状态分开。
- 表单大屏两列、窄屏一列；长文本和上传字段整行。
- 页面不使用卡片套卡片，不用大面积渐变，不用超大标题，不写介绍界面功能的宣传文案。
- 所有按钮、表头、菜单和提示使用 docs/V2现代化UI风格规范-初版.md 中的术语。

验证要求：
1. git diff --check。
2. 对本次修改文件执行 ESLint；不得用全项目自动修复污染无关文件。
3. 执行 ts:check，并区分本次错误和历史错误。
4. 执行 build:local；若失败，列出首个真实错误并判断是否与本次有关。
5. 使用真实后端和真实接口验证首页可访问、药品查询、新增、编辑、审核、驳回、删除及权限显示。
6. 在 1440px、1024px 下检查侧边栏、查询区、表格、抽屉、分页和顶部栏；条件允许时补充 768px。
7. 检查浏览器控制台，不得出现本次新增错误。
8. 保存修改后同路由、同视口截图，并与基线截图对比。

完成后请按以下格式报告：
1. 当前分支和工作区基线。
2. 原型与现有系统差异。
3. 实际修改文件。
4. 公共设计令牌和外壳改动。
5. 两个 V0 页面完成情况。
6. 保留的业务行为。
7. ESLint、ts:check、build 和浏览器验收结果。
8. 修改前后截图路径。
9. 历史问题、未完成项和风险。
10. 等待我确认的视觉决策。

如果真实服务无法启动，不得用 Mock 冒充验收；完成可验证的静态检查后准确报告阻塞原因。遇到与方案冲突的现有代码时，以真实源码和不破坏业务为优先，说明差异后采用最小改动。现在先执行审计和 V0，不要批量修改其他成员页面。
```

## V0 确认后的继续提示词

```text
我已确认 FirstSun V2 现代化 UI 的 V0 方向。请继续严格遵循 docs/V2现代化UI风格规范-初版.md 和 docs/前端界面统一规范.md，将已确认的公共样式应用到我指定的业务模块。

本轮只允许修改以下成员范围：请在这里填写成员字母、目录和页面，例如“B：admin-ui/src/views/pharmacy/purchase”。不要修改其他成员目录，不要再次调整全局设计令牌、系统外壳或公共组件；确需调整时先报告原因和影响范围，等待确认。

实施前先列出目标页面、对应 V2 原型、现有接口和权限；选一个代表页面完成并截图确认，再迁移同模块其他页面。保留所有真实接口、权限、字典、分页、校验和业务操作；不使用 Mock，不引入新 UI 框架，不提交、不合并、不推送。完成后执行目标文件 ESLint、ts:check、build:local 和 1440px/1024px 浏览器验收，并区分本次问题与历史问题。
```
