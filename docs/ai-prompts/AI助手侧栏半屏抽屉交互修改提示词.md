# AI 助手侧栏半屏抽屉交互修改提示词

> 适用场景：AI 助手后端或聊天页已经存在，但左侧导航没有入口，或者当前入口以普通页面路由打开。将以下提示词完整交给编码 AI 执行。

## 完整提示词

````text
请修改当前项目的管理端 AI 助手入口与交互方式，严格按下述需求实现并完成实际验证。

【项目路径】
D:\github-2\FirstSun Pharmacy Management System

【现状与问题】

当前页面左侧导航栏没有显示“AI助手”。之前生成的方案或提示词只是文档，不会自动产生菜单、权限、布局组件或前端入口。

本次不要把“AI助手”实现成普通业务路由页面，也不要点击后替换当前主页面。AI 助手应是一个布局级的全局抽屉工具：用户在任何管理端业务页面中都能打开，关闭后仍停留在原页面。

【必须先阅读并检查】

1. `docs/开发规范与AI协作规则.md`
2. `docs/AI助手可行性分析与实现方案.md`
3. `admin-ui/src/layout/Layout.vue`
4. `admin-ui/src/layout/components/useRenderLayout.tsx`
5. `admin-ui/src/layout/components/Menu/src/Menu.vue`
6. `admin-ui/src/layout/components/TabMenu/src/TabMenu.vue`
7. `admin-ui/src/store/modules/app.ts`
8. `admin-ui/src/store/modules/permission.ts`
9. `admin-ui/src/views/ai/chat/index/index.vue`
10. `admin-ui/src/api/ai/chat/`
11. 当前 AI 原型新增的 pharmacy AI 页面、API、store 和 SQL 迁移（如果存在）

先检查 Git 状态，保留所有用户未提交修改。先报告当前 AI 页面、接口、权限和左侧菜单的真实实现，再列出准备修改的文件及简短计划。不要猜测文件路径。

【目标交互】

1. 在左侧导航栏的菜单列表下方增加一个一级入口“AI助手”；
2. “AI助手”与“首页”“药店业务”“处方支付管理”“药店POS管理”等入口视觉上属于同一侧栏；
3. 入口固定在左侧导航栏下部，位于正常业务菜单列表之后；当菜单内容过多时，业务菜单区域可以滚动，但 AI 助手入口应保持可见；
4. 入口图标使用与现有 Icon 体系兼容的机器人、魔法棒或聊天图标，不引入新的图标库；
5. 用户点击“AI助手”时，不切换当前路由、不新增 TagsView 标签、不改变面包屑，也不卸载当前业务页面；
6. 页面右侧出现 AI 聊天抽屉，动画方向为从右向左滑入；
7. 桌面端抽屉宽度约为可用主内容区的 50%，推荐 `clamp(560px, 50vw, 960px)`，但不得覆盖左侧导航栏；
8. 抽屉打开后，抽屉以外的主内容区显示半透明灰色遮罩；
9. 遮罩从左侧导航栏右边缘开始，只覆盖顶部工具栏、标签栏和主内容区；左侧导航栏保持原色、原尺寸和可见状态；
10. 点击灰色遮罩时，抽屉向右滑回并关闭；
11. 点击抽屉右上角关闭按钮或按 Esc 也应关闭；
12. 关闭后恢复打开前的左侧菜单选中状态，当前路由、滚动位置和表单内容不变；
13. 抽屉打开期间，“AI助手”入口显示选中态；这只是临时视觉选中，不应改变路由；
14. 抽屉关闭后，“AI助手”选中态取消，原路由对应菜单重新显示选中；
15. 抽屉关闭和再次打开时，聊天会话、当前选中会话、已经加载的聊天记录、未发送输入内容和消息滚动位置均保留；
16. 关闭抽屉不能销毁聊天组件。除非用户退出登录或主动清空聊天，否则不要重置状态；
17. 刷新浏览器后至少从后端重新加载既有会话和聊天记录。是否恢复未发送草稿可使用 sessionStorage，但不得在 localStorage/sessionStorage 保存访问令牌或敏感业务结果；
18. AI 正在流式生成时关闭抽屉，不应自动终止生成；再次打开后应看到继续生成或最终结果。只有用户点击“停止生成”才中止请求；
19. 左侧导航折叠时，“AI助手”只显示图标并提供 tooltip；展开时显示图标和文字；
20. 响应式：桌面端按半屏抽屉实现；小屏端允许占满主内容区，但仍要正确关闭且不能出现横向溢出。

【关键技术判断】

“AI助手”是布局动作入口，不是普通路由菜单。

不要通过 `router.push('/ai/...')` 打开，不要给它新增 TagsView，也不要为了显示入口而伪造一个会跳转的 `system_menu` 页面路由。否则无法可靠实现关闭后恢复原菜单选中、保留当前业务页面状态。

推荐结构：

```text
Layout
├─ 左侧 Menu
│  ├─ 可滚动业务菜单
│  └─ 固定 AI 助手动作入口
├─ 当前业务内容（保持挂载）
├─ 仅覆盖主内容区的遮罩
└─ AI 助手抽屉（保持挂载，使用显示状态控制）
````

【推荐实现方式】

一、增加布局级 UI 状态

创建独立 Pinia store，例如：

```text
admin-ui/src/store/modules/aiAssistant.ts
```

至少保存：

- `opened`：抽屉是否打开；
- `initialized`：聊天内容是否已经初始化；
- 必要的 UI 状态，如抽屉尺寸或草稿；
- `open()`、`close()`、`toggle()`。

不要把抽屉开关写入路由 query，也不要让开关动作改变当前 route。

聊天会话和消息以已有后端 API 为准。若现有 AI Chat 组件把关键状态全部封装在组件内部，应通过 `v-show`、CSS visibility/transform 或等价方式保持组件实例，不要用关闭即卸载的 `v-if`。可以首次打开时延迟挂载，首次挂载后保持实例。

二、增加侧栏动作入口

优先在现有 Menu 的垂直模式中加入一个独立 footer/action slot 或组件，不要把它混入后端动态路由数组。

推荐新增组件：

```text
admin-ui/src/layout/components/AiAssistant/AiAssistantMenuEntry.vue
```

要求：

- 样式匹配现有 `.el-menu-item`；
- 展开/折叠行为匹配侧栏；
- 打开时显示 active 样式；
- 关闭时不覆盖 `Menu.vue` 基于 currentRoute 计算的 `activeMenu`；
- 只有具备 AI 助手使用权限的用户才显示；
- 不应调用路由跳转。

把 Menu 垂直布局调整为“上方可滚动菜单 + 下方固定 AI 入口”。水平菜单布局不强制显示该入口；本项目截图所示的经典左侧导航布局必须正确显示。

如果项目支持多种布局，至少保证 classic/sidebar-nav 布局不回归，并对其他布局采用合理降级，例如在顶部工具栏显示 AI 图标按钮。不要为了本需求大规模重写全部布局。

三、增加全局抽屉宿主

推荐新增：

```text
admin-ui/src/layout/components/AiAssistant/AiAssistantHost.vue
admin-ui/src/layout/components/AiAssistant/AiAssistantDrawer.vue
```

将 Host 挂到 `Layout.vue` 或所有布局模式共享的最外层容器中，只创建一个实例。

不要直接使用默认 `el-drawer` 的全屏 modal 行为，因为默认 teleport 到 body 的遮罩通常会覆盖左侧导航栏。以下方案任选其一，选择与当前布局最简单、最稳定的一种：

1. 自定义布局内 fixed/absolute drawer + mask，并动态计算主内容区左边界；
2. 使用 `el-drawer`，但关闭 body teleport，将其挂载在主内容容器，并严格控制 modal 与 drawer 的定位范围；
3. 使用 portal/teleport 到一个位于侧栏之后的专用 overlay root。

无论采用哪种方式，都必须通过实际浏览器验证：遮罩和抽屉绝不覆盖左侧导航栏。

四、尺寸与层级

桌面展开侧栏时：

```css
left: var(--left-menu-max-width);
width: calc(100vw - var(--left-menu-max-width));
```

桌面折叠侧栏时：

```css
left: var(--left-menu-min-width);
width: calc(100vw - var(--left-menu-min-width));
```

这些只是语义示例，应结合现有 `useRenderLayout.tsx` 的布局模式实现，不要硬编码截图中的像素宽度。

层级要求：

- 左侧侧栏在遮罩之外，保持正常显示；
- 主内容遮罩高于页面内容和顶部工具栏；
- 抽屉高于遮罩；
- 全局消息提示、确认弹窗需要高于抽屉；
- 不得破坏现有设置抽屉、弹窗、下拉框、日期选择器的层级。

遮罩建议为：

```css
background: rgb(0 0 0 / 38%);
```

动画使用约 240～320ms 的 ease 过渡，并支持 `prefers-reduced-motion`。

五、聊天界面适配

优先复用现有：

```text
admin-ui/src/views/ai/chat/index/index.vue
admin-ui/src/api/ai/chat/
```

但不要直接把一个依赖“全页面绝对定位”的页面生硬塞进半屏抽屉。应做最小组件化调整：

- 抽取或包装为可嵌入容器的 ChatWorkspace；
- 用容器的 `width: 100%; height: 100%`，而不是相对整个 AppView 的 absolute inset；
- 半屏时压缩或折叠对话列表，避免聊天消息区太窄；
- 保留已有 SSE、停止生成、会话切换和历史消息 API；
- 已经实现的药店 AI 工具结果卡片与写操作确认卡片必须继续可用；
- 不复制第二套聊天状态和 API；
- 不重写后端 AI 逻辑，除非发现接口确实缺失。

推荐抽屉布局：

```text
┌──────────────────────── AI助手 ────────── [关闭] ┐
│ [新对话] [历史会话/收起]                         │
├─────────────────────────────────────────────────┤
│                                                 │
│                 聊天消息区域                    │
│                                                 │
├─────────────────────────────────────────────────┤
│ 输入框                                  [发送]  │
└─────────────────────────────────────────────────┘
```

六、权限

AI 入口必须有明确权限，例如 `pharmacy:ai:chat`。但由于入口不是普通路由菜单，不能只依赖动态路由是否返回来判断显示。

可以新增权限按钮/能力记录并绑定角色，前端使用现有 `checkPermi` 或用户权限集合控制入口显示。数据库变更必须新增 `sql/migrations/` 脚本，不修改历史迁移。

开发环境演示角色必须绑定此权限，否则即使组件实现正确，入口仍然不会显示。迁移脚本应幂等或至少具备明确的重复执行保护，并说明执行后是否需要重新登录或刷新权限缓存。

如果 AI 模块没有启用、当前用户没有权限、菜单迁移未执行或权限缓存未刷新，页面都可能看不到入口。请在最终说明中分别列出诊断方法。

【关闭与状态保留规则】

关闭抽屉时只修改 `opened=false`，不得执行：

- 路由跳转；
- 清空 activeConversationId；
- 清空 messageList；
- 清空输入框草稿；
- abort 正在进行的 SSE；
- 删除会话；
- 重建 ChatWorkspace。

用户退出登录时应停止流、清理仅属于该用户的内存状态和草稿，避免下一个用户看到前一个用户的内容。

【不要这样实现】

1. 不要把 AI 助手做成点击后进入 `/ai/chat` 的普通页面；
2. 不要给它新增浏览器内部标签页或 TagsView；
3. 不要用默认全屏遮罩覆盖左侧导航；
4. 不要在关闭抽屉时销毁聊天组件；
5. 不要用全局事件总线堆叠匿名事件且不清理；
6. 不要复制现有 Chat 页形成两套消息状态；
7. 不要硬编码侧栏宽度为截图像素；
8. 不要顺手重构所有 Layout；
9. 不要仅加入前端按钮而遗漏权限迁移与角色绑定；
10. 不要只检查编译通过而不做浏览器交互验证。

【测试与验收】

请完成自动化检查，并使用浏览器实际操作验证下列场景：

1. 使用具备权限的账号登录后，左侧菜单底部可见“AI助手”；
2. 无权限账号看不到入口；
3. 在收银台页面点击“AI助手”，URL、面包屑和 TagsView 均不改变；
4. 抽屉从右向左进入，宽度约占主内容区一半；
5. 遮罩覆盖业务内容，但不覆盖左侧导航；
6. 打开时 AI 入口选中，原菜单临时取消选中；
7. 点击灰色区域，抽屉向右退出；
8. 关闭后收银台重新显示为选中项；
9. 关闭前选中的聊天会话、消息、草稿和滚动位置在再次打开后仍保留；
10. 关闭时正在生成的回复不会被自动中止；
11. 折叠侧栏后入口图标和 tooltip 正常，遮罩左边界随侧栏宽度变化；
12. 展开侧栏后入口文字恢复，抽屉位置正确；
13. 在首页、药品管理、库存页面分别打开，关闭后各自页面状态不丢失；
14. 按 Esc 和点击关闭按钮均能关闭；
15. 抽屉内下拉菜单、确认弹窗和消息提示层级正确；
16. 浏览器刷新后能重新加载历史会话；
17. 页面不存在横向滚动条、双重纵向滚动或抽屉内容溢出；
18. AI 服务不可用时入口和抽屉可正常关闭，原业务页面不受影响。

至少运行：

- 前端 TypeScript 类型检查；
- 与修改文件相关的 ESLint/格式检查；
- 前端生产或本地构建；
- 如增加权限迁移，执行静态 SQL 检查；
- 如项目已有 E2E 测试框架，补充抽屉开关和状态保留测试。

浏览器验证时保留截图，至少包括：

1. AI 入口出现在展开侧栏；
2. 抽屉打开且左侧导航未被遮罩；
3. 折叠侧栏下抽屉打开；
4. 关闭后原菜单恢复选中。

【成功标准】

只有满足以下全部条件才能声明完成：

1. “AI助手”入口真实显示在左侧导航下部；
2. 点击不触发路由跳转；
3. 抽屉只占主内容区约半屏；
4. 遮罩不覆盖左侧导航；
5. 点击遮罩、Esc、关闭按钮都能关闭；
6. 关闭后原菜单恢复选中；
7. 聊天记录、会话、草稿和滚动位置保留；
8. 流式生成不会因关闭抽屉被意外终止；
9. 权限控制生效，迁移和角色绑定有明确说明；
10. 类型检查、构建和实际浏览器交互验证通过。

【最终交付说明】

请最终列出：

1. 未显示 AI 助手的实际根因；
2. 修改和新增的所有文件及用途；
3. 是否新增 SQL、如何执行、绑定了哪些角色、是否需要重新登录；
4. 抽屉状态保存方案和关闭时为什么不会丢失聊天记录；
5. 实际运行的检查及结果；
6. 浏览器验证步骤和截图路径；
7. 未完成项或已知限制。

现在先检查 Git 状态及上述文件，给出真实根因、简短计划和预期修改文件，然后直接实施，不要只输出示例代码或方案文档。

