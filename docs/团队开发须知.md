# FirstSun 药店管理系统协同开发须知

本文档适用于所有项目成员。开始开发前，请完整阅读并遵守以下约定。

## 1. 统一开发环境

| 组件 | 统一版本 |
| --- | --- |
| Java / JDK | 17 或更高版本 |
| Spring Boot | 3.5.15 |
| Maven | 3.9.x |
| Node.js | 22.x |
| pnpm | 11.22.0 |
| MySQL | 8.x |
| Redis | 7.x |

成员的安装目录可以不同，不要把 JAVA_HOME 或任何本机绝对路径写入项目文件。开始后端开发前，执行 java -version 和 mvn -version，两者都必须显示 Java 17 或更高版本。本项目后端基于 RuoYi-Vue-Pro 官方 master-jdk17 分支，禁止再引入仅支持 JDK 8 或 Spring Boot 2 的依赖和代码。

## 2. 首次获取项目

确保电脑已安装 Git 和 Docker Desktop，然后执行：

```powershell
git clone https://github.com/HaiMingQAQ/FirstSun-Pharmacy-Management-System.git
cd FirstSun-Pharmacy-Management-System
Copy-Item .env.example .env
docker compose up -d
docker compose ps
```

默认服务地址：

| 服务 | 地址或端口 |
| --- | --- |
| 管理端 | <http://localhost> |
| 后端接口 | <http://localhost:48080> |
| MySQL | `127.0.0.1:3307` |
| Redis | `127.0.0.1:6379` |
| 数据库 | `firstsun_pharmacy` |

根目录 `.env` 是成员个人电脑的配置文件，**禁止提交到 GitHub**。

## 3. 创建功能分支

所有功能分支必须从最新的 `main` 创建：

```powershell
git switch main
git pull origin main
git switch -c feat/a-store
git push -u origin feat/a-store
```

建议使用以下分支名称：

```text
feat/a-store
feat/b-medicine
feat/c-purchase
feat/d-sale
feat/e-member
feat/f-finance
```

新任务使用 `类型/成员-功能` 命名，例如：

```text
feat/a-store-employee
fix/c-purchase-validation
```

**禁止直接在 `main` 分支开发或推送。**

## 4. 日常开发流程

每天开始开发前，先同步主分支：

```powershell
git switch main
git pull origin main
git switch 自己的分支名
git merge main
```

完成一个小功能后及时提交：

```powershell
git add .
git commit -m "feat: 完成门店信息管理"
git push
```

随后在 GitHub 创建 Pull Request：

```text
自己的功能分支 → main
```

Pull Request 必须由至少一名其他成员审核。合并后，其他成员应及时更新自己的分支。

## 5. 提交信息规范

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| `feat` | 新增功能 | `feat: 新增门店员工管理` |
| `fix` | 修复问题 | `fix: 修复药品库存计算错误` |
| `docs` | 修改文档 | `docs: 补充项目启动说明` |
| `style` | 调整页面样式 | `style: 调整订单列表布局` |
| `refactor` | 重构代码 | `refactor: 重构会员查询逻辑` |
| `chore` | 修改配置或构建环境 | `chore: 更新 Docker 配置` |
| `test` | 添加或修改测试 | `test: 添加库存服务测试` |

一个提交尽量只完成一件事，不要把多个无关功能放进同一次提交。

## 6. 文件修改范围

每位成员主要修改自己负责的模块。修改以下公共文件前，必须先在小组内说明：

```text
docker-compose.yml
.env.example
pom.xml
package.json
pnpm-lock.yaml
公共配置文件
权限和菜单配置
数据库初始化脚本
```

禁止提交以下内容：

```text
.env
node_modules/
target/
日志文件
个人密码或密钥
无关的 IDE 配置
```

## 7. 包管理器规范

管理端统一使用 `pnpm`。不要交替运行 `npm install` 和 `pnpm install`，避免产生不同的锁文件。

```powershell
corepack enable
pnpm install
```

只保留项目现有的 `pnpm-lock.yaml`，不要提交新生成的 `package-lock.json`。

安装新依赖后，需要同时提交：

```text
package.json
pnpm-lock.yaml
```

## 8. 数据库修改规范

数据库结构发生变化时，在 `sql/migrations` 目录新增增量脚本，例如：

```text
sql/migrations/20260908_a_add_store_employee.sql
```

要求：

- 文件名包含日期、成员标识和修改内容。
- SQL 与对应代码放在同一个 Pull Request 中。
- 不要多人同时修改初始建库脚本。
- 不要仅修改自己电脑里的数据库而不提交 SQL。
- 合并前由相关模块负责人检查表名、字段名和索引。

拉取新的增量脚本后，应按照脚本顺序执行。

只有需要完全重建本地数据库时，才执行：

```powershell
docker compose down -v
docker compose up -d
```

> **警告：** `docker compose down -v` 会清空 Docker 中的本地数据库数据。执行前必须确认没有需要保留的数据。

## 9. 冲突处理

发生冲突时，不要删除其他成员的代码，也不要擅自执行：

```text
git reset --hard
git push --force
```

应先停止合并，在小组内说明冲突文件，由涉及该模块的成员共同确认处理方式。

## 10. Pull Request 提交前检查

提交 Pull Request 前，确认：

- [ ] 自己负责的功能可以正常打开和操作。
- [ ] 后端可以正常启动。
- [ ] Docker 服务状态正常。
- [ ] 没有提交 `.env`、密码、密钥等敏感信息。
- [ ] 没有提交 `node_modules`、`target` 或日志文件。
- [ ] 数据库结构变更已提供增量 SQL。
- [ ] 已同步最新 `main` 并处理冲突。
- [ ] Pull Request 描述写明修改内容和验证方式。

## 11. 常用命令

查看当前分支和文件状态：

```powershell
git status
```

查看 Docker 服务：

```powershell
docker compose ps
```

查看服务日志：

```powershell
docker compose logs -f
```

停止服务：

```powershell
docker compose down
```

同步 `main` 到自己的功能分支：

```powershell
git switch main
git pull origin main
git switch 自己的分支名
git merge main
```
