# FirstSun 药店管理系统 V2 现代化 UI 风格规范（初版）

版本：0.1
适用范围：`admin-ui` 药店管理端
维护责任：A 负责公共设计基础和系统外壳，A～F 分别负责自己的业务页面

## 1. 文档目标

本规范用于把 V2 原型统一落地到现有 yudao Vue3 + Element Plus 管理端。V2 是信息架构和业务流程参考，不是要求复制其静态 HTML、旧式阴影、渐变或写死数据。

升级后的产品应当：

- 第一眼明确是 FirstSun 药店管理系统，而不是 yudao 演示后台。
- 保持专业、清晰、可信赖，适合药店人员高频使用。
- 在六名成员分别开发的情况下仍保持一致的页面结构和交互。
- 保留登录、动态菜单、权限、字典、路由、多页签、分页和真实接口。
- 通过少量公共令牌和既有 Element Plus 组件实现，不建立第二套 UI 框架。

## 2. 设计关键词

```text
现代药店运营工作台
专业
清晰
可信赖
高效
克制
易扫描
低学习成本
```

不采用以下方向：营销网站、玻璃拟态、大面积渐变、超大圆角、装饰性图形、卡片堆叠、纯深色科技风、静态大屏看板。

## 3. 品牌与视觉基线

### 3.1 品牌呈现

- 系统名称统一为“FirstSun 药店管理系统”。
- 左上角品牌区必须清晰显示系统名称和正式 Logo。
- 未获得正式 Logo 时只能使用现有资产作为临时占位，并在交付报告中注明；禁止用 emoji 或 AI 临时图标冒充正式 Logo。
- 不在业务页面重复放置大型品牌标识。

### 3.2 色彩令牌

| 用途 | 建议值 | 使用说明 |
| --- | --- | --- |
| 品牌主色 | `#176B5B` | 侧边栏重点、主按钮、选中态 |
| 交互强调 | `#16A085` | 链接、悬停、辅助强调 |
| 页面背景 | `#F5F7F8` | 管理端主内容背景 |
| 面板背景 | `#FFFFFF` | 查询区、表格和表单内容面 |
| 主文字 | `#1F2933` | 标题、关键数据和正文 |
| 次级文字 | `#667085` | 描述、辅助字段和提示 |
| 弱文字 | `#98A2B3` | 占位、次要时间和禁用内容 |
| 边框 | `#E4E7EC` | 输入框、分隔线和面板边界 |
| 浅边框 | `#F0F2F5` | 表格分隔和弱层级 |

成功、警告、危险和信息状态使用 Element Plus 语义色或项目字典映射，不允许各页面自行发明状态颜色。

### 3.3 字体

- 沿用项目系统字体栈，不新增网络字体。
- 页面标题建议 `20px/28px`，字重 600。
- 区块标题建议 `16px/24px`，字重 600。
- 表单、表格和正文以 `14px/22px` 为主。
- 辅助说明可使用 `12px/20px`，不得小于 12px。
- 不使用随视口宽度缩放字体，不使用负字间距。

### 3.4 圆角、边框与阴影

- 常规输入框、按钮、面板使用 `6px` 或 `8px` 圆角。
- 标签使用组件默认小圆角，不统一改成胶囊形。
- 页面区块以边框和间距建立层级，阴影只用于抽屉、弹窗和悬浮菜单。
- 禁止卡片嵌套卡片，禁止每个字段或指标都做成独立浮动卡片。

### 3.5 间距

统一采用 `4px/8px` 基础体系：

```text
4px：图标与紧凑文字
8px：按钮组、标签和紧凑控件
12px：关联字段
16px：常规组件间距
24px：页面区块间距
32px：重要内容区分隔
```

不得在业务页面随意使用互不相关的 `13px`、`19px`、`27px` 等间距。

## 4. 系统外壳

### 4.1 左侧导航

- 保留动态菜单、权限过滤、折叠和路由行为。
- 品牌区、菜单项、选中态和悬停态使用统一设计令牌。
- 一级菜单使用统一图标尺寸，图标与文字对齐。
- 菜单项不是卡片，不增加装饰性边框或大阴影。
- 选中项应清晰但不过度发光；建议使用主色背景或浅主色底配主色文字。
- 菜单名称遵循业务术语，不出现开发框架宣传入口。

### 4.2 顶部栏与多页签

- 保留用户、租户、全屏、通知等现有有效能力。
- 顶部栏主要用于全局操作，不放业务表单按钮。
- 多页签保持紧凑，选中页签具有明确边界和关闭状态。
- 顶栏、页签和主内容之间使用细边框区分，不使用重阴影。

### 4.3 页面内容区

- 页面背景使用冷灰白，业务内容面使用白色。
- 标准页面由页面标题、查询与操作、数据主体、分页组成。
- 不设置营销式 Hero，不用介绍性大段文案解释页面功能。
- 页面主内容宽度充分利用后台空间，但保留稳定的 `16px～24px` 外边距。

## 5. 页面模板

### 5.1 工作台首页

首页只展示与药店运营有关的信息：

- 今日销售额和订单数。
- 库存预警与临期药品。
- 待审核业务和待办事项。
- 销售趋势。
- 常用业务快捷入口。

已有真实接口才能显示具体数字；没有接口时显示规范空状态，不使用随机数据。指标区数量应克制，图表用于比较和趋势，不作为装饰。

### 5.2 简单 CRUD

参考：`admin-ui/src/views/pharmacy/base/category`。

- 高频查询条件直接展示。
- 新增、导出等主操作位于表格上方。
- 表格首先展示名称、编码等识别字段。
- 简单新增和编辑使用 `Dialog`。
- 删除、停用等危险操作必须二次确认。

### 5.3 复杂档案页面

参考：`admin-ui/src/views/pharmacy/base/drug`。

- 默认查询区只放高频条件，低频项收入“更多筛选”。
- 表格操作采用“主操作 + 更多”。
- 字段较多时使用响应式 `el-drawer`。
- 表单使用连续分区，不用 Tabs 隐藏校验错误。
- 大屏两列、窄屏一列，上传和长文本字段整行。

### 5.4 流程与审核页面

- 当前业务状态放在页面容易识别的位置。
- 审核状态、启停状态、支付状态和单据状态不得混成一个标签。
- 通过、驳回、退款、作废等操作保留权限控制和二次确认。
- 关键操作按钮顺序保持稳定，不随不同页面任意调整。

## 6. 组件规则

| 场景 | 统一做法 |
| --- | --- |
| 主要命令 | `primary` 按钮，使用明确动词 |
| 图标按钮 | 使用现有 Icon/Element Plus 图标，并提供 tooltip |
| 删除/作废 | 危险语义 + 二次确认 |
| 二元设置 | switch、checkbox 或 radio，不使用两个普通按钮 |
| 枚举选项 | select 或 radio + 既有字典 |
| 数字输入 | `el-input-number`，设置必要精度和范围 |
| 状态 | `dict-tag` 或统一语义 `el-tag` |
| 日期时间 | 项目已有日期组件和格式化函数 |
| 上传 | 复用 `UploadImg`、`UploadImgs`、`UploadFile` |
| 分页 | 复用项目 `Pagination` |
| 空状态 | Element Plus 或项目统一空状态 |
| 加载 | `v-loading`，提交期间禁止重复操作 |

按钮文案使用动词，例如“新增药品”“保存”“审核通过”，不要使用“确定操作”“点击这里”等含糊文案。

## 7. 表格与查询

- 查询项按使用频率排序，默认区域不超过一至两行。
- “查询”和“重置”位置在同类页面保持一致。
- 表头简短，单位写入表头或统一格式化，不在每个单元格重复冗长文字。
- 业务识别字段靠左，金额和数量对齐一致，状态使用标签。
- 长文本截断并提供 tooltip，不让单行内容撑坏布局。
- 优先使用 `min-width`；操作列固定右侧并保持稳定宽度。
- 操作超过两个时，保留一个主要操作，其余放入“更多”。
- 权限必须同时覆盖操作入口和对应业务行为，不得只做视觉隐藏。

## 8. 表单与反馈

- 简单表单使用 Dialog；复杂表单使用 Drawer；完整业务流程可使用独立详情页。
- 相同业务对象使用一致的标签宽度、字段顺序和必填标识。
- 必填校验靠近字段显示，不用 Toast 替代字段错误。
- 后端维护字段不渲染为可编辑输入，也不得原样回传。
- 保存成功后刷新列表和关联映射；失败走统一错误提示，不静默吞掉。
- 删除、审核、驳回、退款、出入库等重要操作必须防重复提交。

## 9. 响应式与可访问性

- 主要验收宽度为 1440px 和 1024px，基础检查宽度为 768px。
- 表单推荐 `:xs="24" :sm="24" :md="12"`，上传和长文本整行。
- 固定格式控件使用稳定尺寸，状态变化不能导致页面跳动。
- 文本不得遮挡、溢出按钮或与相邻内容重叠。
- 键盘焦点状态必须可见；不能只靠颜色表达关键状态。
- 动效控制在 `120～180ms`，并尊重减少动态效果设置。
- 浅色主题为首轮视觉验收标准；现有深色模式不得出现不可读或结构破坏。

## 10. 业务术语

统一使用：

```text
门店
员工
药品分类
药品档案
药品条码
供应商
采购订单
采购收货
批次库存
库存流水
销售订单
销售退货
处方审核

```

不要在同一业务含义中混用“药品、商品、产品、药物”。接口字段无法调整时，可以保留字段名，但页面展示必须使用统一术语。

## 11. 多人协作边界

A 统一维护：

- 全局设计令牌和药店公共样式。
- 系统外壳、品牌区、侧边栏、顶部栏和多页签。
- 药店工作台。
- 药店公共组件。
- 菜单层级、菜单图标和本规范。

A～F 成员各自维护自己的业务目录，不自行修改全局设计令牌、公共布局和公共组件。确需公共修改时先提出变更理由、影响页面和截图，经 A 合并后所有成员同步。

推荐流程：

1. 合并公共 UI 基础。
2. 每个成员更新自己的分支。
3. 每个模块先升级一个代表页面。
4. 提交 1440px 和 1024px 截图进行视觉确认。
5. 确认后再迁移同模块其他页面。
6. 一个提交只包含一个可独立审查的 UI 或业务目标。

## 12. AI 修改约束

- AI 修改前必须阅读本规范和 `docs/前端界面统一规范.md`。
- AI 必须先读真实源码和 V2 原型，不得仅根据截图猜测文件结构。
- 不得覆盖未提交的他人修改，不得批量格式化无关文件。
- 不得新增 UI 框架，不得用 Mock 冒充真实接口。
- 不得为了统一视觉删除接口字段、权限、字典、分页、校验或业务操作。
- 公共能力只在发生真实重复时提取，不创建无实际使用的抽象层。
- 未经明确要求，不提交、不合并、不推送 Git。

## 13. 页面验收清单

- [ ] 系统品牌和当前业务清晰，不再显示无关 yudao 演示内容。
- [ ] 页面符合本规范的颜色、间距、圆角和文字层级。
- [ ] 查询、重置、分页、新增、编辑和业务操作可用。
- [ ] 权限、字典、校验和二次确认没有被弱化。
- [ ] 数据来自真实接口；无接口区域使用空状态。
- [ ] 1440px、1024px 无遮挡、重叠和异常横向溢出。
- [ ] 768px 下核心流程仍可操作。
- [ ] 加载、空数据、接口错误和禁用状态正常。
- [ ] 浏览器控制台无本次新增错误。
- [ ] 目标文件 ESLint 和 TypeScript 无新增错误。
- [ ] PR 或交付报告附带统一尺寸截图。

## 15. V0 落地记录（2026-09-09）

本节记录 V0 阶段实际落地的规则与决策，供 B～F 成员参照实施。原文 1～14 节不变，本节为补充。

### 15.1 公共设计令牌

- 令牌文件：`admin-ui/src/styles/pharmacy/index.scss`，通过 `admin-ui/src/styles/index.scss` 的 `@use` 载入。
- 采用带 `--pharmacy-` 命名空间的 CSS 自定义属性，在 `:root` 声明（仅声明不产生副作用），由药店页面通过 `.pharmacy-page` 等作用域引用。
- **不覆盖 Element Plus 全局变量**（`--el-color-primary` 等系统级主题由 `store/modules/app.ts` 统一管理）。
- B～F 成员业务页面如需统一视觉，根容器添加 `pharmacy-page` 类，子面板使用 `pharmacy-panel`、KPI 使用 `pharmacy-kpi`、快捷入口使用 `pharmacy-shortcut`。
- 令牌清单见文件注释，核心值：主色 `#176B5B`、强调 `#16A085`、页面背景 `#F5F7F8`、面板 `#FFFFFF`、主文字 `#1F2933`、次文字 `#667085`、边框 `#E4E7EC`、圆角 `6px/8px`、间距 `4/8/16/24px`。

### 15.2 系统外壳配色

- 新用户默认主题：`elColorPrimary=#176B5B`、侧边栏背景 `leftMenuBgColor=#0E4A3F`、侧边栏选中 `leftMenuBgActiveColor=var(--el-color-primary)`（即 `#176B5B`）。
- **旧用户主题缓存保留**：`wsCache` 已存主题的旧用户不受影响，新用户或清缓存后获得品牌默认色。不在业务代码中自动清除 `localStorage`/`sessionStorage`/`wsCache`。
- 外壳组件（`Menu`/`TagsView`/`ToolHeader`/`AppView`/`Logo`）均由 CSS 变量驱动，通过令牌即可达成现代化，**不编辑这些组件**以保留动态菜单、权限、折叠、顶部工具、多页签和路由能力。
- 系统标题：`admin-ui/.env` 的 `VITE_APP_TITLE` 改为 `FirstSun 药店管理系统`（与 `.env.docker` 一致）。
- Logo：仅存在通用 `src/assets/imgs/logo.png`，**未伪造品牌 Logo**，作为临时占位，待正式 Logo 资产后替换。

### 15.3 工作台首页 V0

- 路由 `/` → `/index` → `views/Home/Index.vue`，`defineOptions({ name: 'Index' })` 保持不变。
- 移除全部 yudao 演示内容（ruoyi/yudao 仓库卡片、AI/ERP/CRM 快捷入口、假 echarts 数据）。
- 真实数据来源：5 个药店分页接口的 `total`（药品/分类/门店/员工/条码 + 待审核药品数），`pageSize=1` 仅取计数；`Promise.all` 独立请求，任一失败显示"暂无统计数据"，**不编造数字、不用 0 冒充、不显示假趋势图**。
- 经营数据（销售额/订单数/库存预警/临期药品）暂无统计接口，用**单个**降权面板显示"暂无统计接口"提示，不出现一排无意义的"--"。
- 快捷入口跳转真实路由 `/pharmacy/base/{drug|category|store|employee|barcode}`，按 `checkPermi(['pharmacy:base:*:query'])` 控制可见，不写死不存在的路由。

### 15.4 药品档案 V0 视觉统一

- 在已有未提交成果（查询区/表格/抽屉/分页/权限/审核）之上做**小范围视觉增量**，不整文件重写、不回退功能。
- 表格列对齐按本规范 §7：业务识别字段（药品编码/通用名/商品名/规格/分类）`align="left"`，金额（零售价）`align="right"`，状态与操作 `align="center"`。
- 抽屉表单提交按钮文案按本规范 §6 使用动词："确 定" → "保 存"。
- 保留：更多筛选、药品类型与处方属性联合显示、权限下拉、审核与驳回、响应式抽屉、连续分区、上传组件、`createDefaultFormData`、`createDrugPayload`、TypeScript 类型修复。

### 15.5 V0 后续扩散约束

V0 确认前，**仅**完成公共令牌、系统外壳配色、工作台首页 V0、药品档案 V0、规范增补。不改药品分类/门店/员工/条码及 B～F 页面。确认后再按 `docs/ai-prompts/V2现代化UI升级AI执行提示词.md` 的"继续提示词"批量迁移。
