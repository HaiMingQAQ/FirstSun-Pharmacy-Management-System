## 门店范围与权限边界

采用 C 内部保守限制，不冒充团队已提供多门店授权 API：

1. 必须为已认证的管理端 LoginUser；租户上下文必须存在，且与登录用户租户一致。
2. 拒绝 TenantIgnore、跨租户 visit、会员身份或匿名身份。
3. 通过 A `EmployeeService.getEmployeeByUserId` 查询未删除员工；A Mapper 受现有 tenant interceptor 约束。
4. 必须关联当前 userId、状态为 1（在职），storeId 有效。接口省略 storeId 时自动取员工门店；显式传其他门店直接拒绝。
5. 不按岗位或超级管理员身份绕过门店范围。多门店、平台跨租户管理仍需团队授权契约。
6. C 每条 SQL 自身也绑定 tenantId/storeId；所有参与关联的库存表/仓库表核对 tenant、归属及 deleted。仓库不存在和越范围详情统一返回框架 NOT_FOUND，避免探测他店资料。

上述限制只解决当前只读入口，不宣称 B/D/F 来源业务授权已经完成。Token 认证、A 员工查询实际租户 SQL、真实账号权限仍需运行环境验证。

## HTTP 说明

前端 request 使用下表路径；框架管理端前缀通常为 `/admin-api`，不要在客户端重复添加。响应沿用 `CommonResult`：成功 code=0；分页 data 含 list/total。失败沿用现有验证、权限和 NOT_FOUND 错误，不分配未经 A 确认的 C 数值错误码。

| GET 路径 | 权限 | 业务筛选 |
| --- | --- | --- |
| `/pharmacy/inventory/warehouse/page` | `pharmacy:inventory-warehouse:query` | warehouseId、code、name、status |
| `/pharmacy/inventory/warehouse/get?id=...` | 同上 | 正数 id，自动限定员工门店 |
| `/pharmacy/inventory/location/page` | `pharmacy:inventory-location:query` | warehouseId、locationId、code、status |
| `/pharmacy/inventory/batch/page` | `pharmacy:inventory-batch:query` | warehouseId、drugId、batchId、batchNo |
| `/pharmacy/inventory/batch/location-stock` | 同上 | warehouseId、drugId、batchId、locationId、batchNo |
| `/pharmacy/inventory/flow/page` | `pharmacy:inventory-flow:query` | drugId、batchId、locationId、batchNo、bizNo |

分页统一 pageNo>=1、pageSize=1..200，可省略使用默认 1/10；可选 storeId 只允许本人门店。code/name 为字面子串匹配（参数绑定 LOCATE，不将 `%`/`_` 当通配符），batchNo/bizNo 精确匹配。各资源仅支持表中所列筛选，不支持的查询字段不要发送。

- 批次 qtyAvail 是账面可用量，不是经过药品状态/实时效期过滤的可售量。
- 货位库存 qtyAvail=qty-qtyFrozen；maxCapacity 使用 Long 对应 INT UNSIGNED。
- 已停用的仓库/货位和过期批次仍可查询；不按药品当前可售状态截断历史台账。
- 流水查询直接按历史 storeId/tenantId 过滤，不依赖当前药品启用状态；缺少已批准迁移，所以暂不返回 operationId/originalFlowId。
- 成本字段本阶段全部不返回；日后按确认的成本权限另扩展。
