# C 部分需求分析

## 1. 目标与边界

C 负责“库存与库房作业”的前端、后端、库存数据维护与自测。交付目标是让采购收货准确入库、销售扣库不超卖、退货可追溯回补，并用批次、货位与流水证明库存一致。

分工引用的需求编号：`ADM-003/008/009/011/012`、`WH-003/005/007`。下面使用本模块自建编号 `C-01` 等作为实施与测试追踪标识，不替代原需求编号。

| 范围 | 内容 |
| --- | --- |
| C 直接负责 | 仓库、货位、批次库存、货位库存、库存流水、上架移位、盘点、报损、效期预警、库存统一服务 |
| C 协同 | 向 B 提供收货入账；向 D 提供选批、扣库、退货回补；向 F 提供可售量，扩展时提供冻结/释放/冻结转出库 |
| 其他成员负责 | A 药品、门店、员工及公共模块；B 采购和供应商；D 销售、退货业务单及资金；E 处方与支付；F 会员和小程序订单 |
| 不自动扩展 | 跨店调拨、采购退货闭环、拆零单位换算、温湿度设备采集、独立销毁台账、多轮部分销毁、真实支付、离线同步 |

C 不直接更新采购单、销售单、会员或支付表。库存流水中的来源单据用于追溯，不把其他模块业务逻辑移入库存服务。

## 2. 角色与授权

| 业务角色 | 允许能力（权限草案） |
| --- | --- |
| 库管 | 本门店仓库货位维护、库存查询、上架、录入盘点与报损 |
| 店长/库存审批人 | 审批盘点差异、审批报损、处理效期预警；可售条件仍由后端强制检查 |
| 报损执行人和复核人 | 本人认证执行/复核已审批单据；两人身份不同 |
| 收银/POS、采购服务、小程序订单服务 | 通过内部库存契约调用，不能直接写库存表 |
| 系统任务 | 限定租户、门店执行预警刷新和后续冻结到期释放，有审计来源 |

权限包括按钮权限、接口权限及租户/门店数据范围。隐藏按钮不等于授权。门店、租户、操作人不能仅信任请求参数；操作人由当前登录上下文解析，员工与账号映射复用 A 的能力。用户未关联员工或无门店权限时应拒绝。

## 3. 功能需求与优先级

P0 是首个可联调闭环；P1 是 C 分工完整交付；P2 是依赖 F 线上订单等能力的扩展。不能只完成 P0 就宣称 C 全部完成。

| 编号 | 优先级 | 功能与规则 | 完成证据 |
| --- | --- | --- | --- |
| C-01 | P0 | 仓库：门店内编码唯一、名称、温区、默认收货仓、启停；每门店最多一个启用默认仓 | 新增/查询/编辑真实落库；并发设置默认仓仍唯一 |
| C-02 | P0 | 货位：仓库内编码唯一、类型、容量、启停；关联仓库与门店一致 | 重复编码、越权、库存占用时停用/删除被拒绝 |
| C-03 | P0 | 批次/货位库存查询：门店、仓库、货位、药品、批号、效期、质量状态、总量/可用/冻结 | 分页、筛选和详情与真实数据库一致；库存数量无直接编辑入口 |
| C-04 | P0 | B 收货入账：验收通过的收货明细、批号、生产/有效日期、货位、数量、成本 | 部分收货分别入账；重复同一事件不重复增加；失败整体回滚 |
| C-05 | P0 | 选批与销售扣库：FEFO 效期最早优先；同效期按批次 ID、货位 ID 稳定排序 | 跨批次分配可追溯；库存不足、过期、停售、越权拦截 |
| C-06 | P0 | 销售退货回补：关联原销售出库分配、限制累计回补量、恢复原批次货位 | 多次部分退货总量不超原出库量；重复退货不重复回补 |
| C-07 | P0 | 库存流水：来源业务、单号/明细、批次、货位、入出量、冻结变化、余额、成本、人员时间 | 所有库存变动有流水；能由单号查到实际批次/货位分配 |
| C-08 | P1 | 上架/移位：同仓库待上架货位移至正式货位，容量/温区校验，冻结量不可移动 | 总量不变、源减目标增、成对流水、重复不重复移位 |
| C-09 | P1 | 盘点：草稿、开始、明盘/盲盘录数、完成、审批调整 | 差异审批后一次性入账；盲盘 API 不返回账面量；重复审批不重复调整 |
| C-10 | P1 | 报损：草稿、提交、审批、不同身份复核、执行、取消 | 只有合法状态可出库；过期批次允许报损；执行与流水同事务 |
| C-11 | P1 | 效期：按日计算剩余天数、30/60/90 天分级、过期标识、处理记录 | 相同日期重复刷新不重复建提醒；“继续销售”不能绕过过期拦截 |
| C-12 | P1 | 三账核对：批次汇总、货位明细、库存流水及冻结锁记录 | 查询异常并可定位来源；不自动修改库存来掩盖差异 |
| C-13 | P2 | 线上订单冻结、释放、冻结转出库、过期释放 | 与 F 约定唯一扣库时点后实现；重复释放/支付与取消竞争安全 |

## 4. 数量、批次与效期规则

1. 数量使用现有 SQL 的整数单位，P0 按药品统一销售单位计数，不实现盒/粒混算。数量必须大于零且不溢出 INT；聚合使用更宽整数并校验落库范围。
2. 批次身份以现有唯一键 `(tenant_id, warehouse_id, drug_id, batch_no)` 为准。同批号在不同仓库是不同批次，不能仅以批号定位。
3. 相同批次再次收货必须校验有效日期、生产日期等元数据。差异返回业务冲突，不静默覆盖历史批次；供应商变化须由 B/C 确认追溯策略。
4. `qty_total = qty_avail + qty_frozen`；`qty_sold` 是累计净销售量，不参与在库守恒。
5. 每个批次 `qty_total = SUM(货位.qty)`，`qty_frozen = SUM(货位.qty_frozen)`；货位可用量为 `qty - qty_frozen`。
6. 可售量还需过滤药品审核/启用、批次质量、仓库货位启用和实时有效日期。账面 `qty_avail` 不必等于可售量，过期库存可仍在账上。
7. 有效期边界拟采用业务时区 `Asia/Shanghai`，`expiry_date < 当天` 为过期，到期当日允许销售；这是产品规则草案，需 B/D 确认，非药品法规结论。后端通过可注入时钟实时判断，不能依赖异步 `expiry_status`。
8. 正常扣库禁止减少冻结量；冻结转出库才同时减少在库量与冻结量。移位不改变累计净销售量。
9. 质量异常、召回、过期药品禁止销售，但库存查询、历史追溯、合法退货回补与报损仍应可用。
10. P0 只自动回补已核验原销售分配且状态正常的退货。质量待判定/异常退货需专门隔离策略后接入，不可自动变为可售；过期回补仍不可售。原货位不可用时返回明确待处理，不擅自改成另一个批次。

效期分级拟定为：剩余天数小于0单独标识“已过期”并归红色风险；0～30天一级红，31～60天二级橙，61～90天三级黄，超过90天不生成新预警。已有提醒作为历史保留。阈值及到期当日规则一起交由团队确认。

## 5. 作业状态

### 盘点

沿用 SQL：`0 草稿 → 1 进行中 → 2 已完成 → 3 已调整`。

- 草稿可编辑范围；开始后固定为单仓库范围，保存批次/货位账面快照。
- 一期采用短时仓库作业冻结：开始前不得存在未处理订单冻结；盘点状态为 1/2 时拦截该仓库其他库存变更；进入状态 3 后释放作业冻结。
- 作业冻结是仓库写入门禁，不将全部库存额外写成 `qty_frozen`，避免混淆订单占用；由所有写入路径统一检查。
- 录入 `real_qty=0` 有意义；`NULL` 是未盘，不能自动当作零。差异由服务端计算。
- “完成”要求全部明细录入；“审批调整”要求独立审批权限，快照仍有效且库存守恒；全单一次性提交，即使零差异也完成状态转换。
- 审批驳回拟从 2 返回 1 并记录意见，继续冻结。取消与审批意见当前缺少完整状态/字段，P1 需增量迁移后才能提供；取消不得产生调整流水，释放仓库门禁并保留历史。
- 不把“全场、多仓库、边营业边盘点”默认算入一期；后续另行设计持续变更差异算法。

### 报损

沿用 SQL：`0 草稿 → 1 待审批 → 2 已审批 → 3 已执行`，执行前允许受控进入 `4 已取消`；审批驳回拟返回草稿并保留意见。

提交后明细不可随意修改。审批不扣库，执行时重新检查数量，库存不足则整单失败，不能产生负库存。复核人必须通过自己的认证操作写入，不能由执行人填写一个不同 ID 冒充复核。执行、复核身份不同；需要保留复核时间与意见的字段见迁移草案。

一期执行只支持已定义的报损流程；报溢、退供应商和多次部分处置不自动开放。现有销毁字段可记录一次处置证据，不宣称具备独立销毁台账或完整监管合规能力。

## 6. 页面规划

所有拟建页面位于 `admin-ui/src/views/pharmacy/inventory/`，API 位于 `admin-ui/src/api/pharmacy/inventory/`。

| 页面子目录 | 列表/详情关键内容 | 主要动作 |
| --- | --- | --- |
| `warehouse` | 门店、编码、名称、温区、默认、状态 | 新增、编辑、启停 |
| `location` | 仓库、货位码、类型、容量、占用、状态 | 新增、编辑、启停 |
| `batch` | 药品、批号、仓库、有效期、账面量、可售量、质量 | 查看货位、流水；无通用库存编辑 |
| `flow` | 来源单号、时间、类型、货位、入/出/冻结变化、余额 | 条件查询、查看来源标识 |
| `putaway` | 批次、源/目标货位、可移动量 | 提交同仓移位 |
| `stocktake` | 单号、仓库、状态、盘点进度、差异 | 开始、录数、完成、审批/驳回、取消 |
| `damage` | 单号、原因、状态、成本、执行/复核记录 | 提交、审批/驳回、复核、执行、取消 |
| `expiry` | 到期日、剩余天数、预警级别、处理记录 | 筛选、刷新、标注处理 |
| `reconciliation` | 批次/货位/流水/冻结差异 | 只读核对、定位异常 |

使用现有 `ContentWrap`、`Dialog`、`Pagination`、`dict-tag`、Element Plus、权限指令与统一请求错误处理。简单资料用弹窗，复杂盘点/报损用抽屉或详情页。A 标准页面需先进入可用基线再复用，不从参考分支直接复制全局样式。

每页必须覆盖加载中、无数据、接口失败、权限不足、校验错误及防重复提交状态。仓库/货位存在库存、有效锁、未完结作业时不得删除或停用；历史流水、批次不提供物理删除入口。

## 7. 验收示例

以同一仓库、同一药品两个正常批次建立真实测试数据，A 批次有效期早于 B：

1. 收货 A 10、B 8；重复 A 的原收货请求，总量仍为 18。
2. 销售 12，FEFO 分配 A 10、B 2；在库 6，净销售 12；保留每个货位实际分配。
3. 回补原 A 出库 3，在库 9、净销售 9；重复同一退货事件保持不变。
4. 对 A 所在货位盘点：账面 3、实盘 2；独立审批后总在库 8、净销售仍为 9。
5. B 报损 1，经审批、复核、执行后总在库 7；重复执行不变化。
6. 再检查批次量、货位量、净入出流水，三者一致。

另行测试并发扣减、跨门店访问、过期边界、质量停售、冻结库存、重复事件换参数、事务中途失败。完整测试矩阵见执行计划。
