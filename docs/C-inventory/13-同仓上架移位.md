# C-08 同仓上架移位

## 接口

`POST /pharmacy/inventory/movement/execute`

权限：`pharmacy:inventory-movement:execute`。请求必须带稳定的 `bizNo` 和行 `bizLineId`；同一请求重试会重放已完成结果，不再次移动库存。

```json
{
  "warehouseId": 12,
  "bizNo": "MV-ABC123",
  "lines": [{
    "bizLineId": 1,
    "batchId": 101,
    "sourceLocationId": 201,
    "targetLocationId": 202,
    "qty": 3
  }]
}
```

## 规则

- 仅同仓库。仓库、批次、源/目标货位均需属于登录员工门店且启用。
- 源货位只可移动 `qty - qty_frozen`；冻结库存不能移动。
- 按源/目标货位最终净变化校验容量；批次 `qty_total`、`qty_avail`、`qty_frozen`、`qty_sold` 不变。
- 每行写两条 `ph_inv_flow`：源 `out_qty`、目标 `in_qty`，均为 `flow_type=60`、`biz_type=8`。
- 任一步失败，库存和流水同一事务回滚。

现有 `ph_location` 没有“待上架”类型和货位温区字段，因此接口不声称校验不存在的数据列；移位目标由库管从本仓启用货位选择。

## 验证

`InventoryMovementServiceTest` 覆盖正常移位、完整重试、冻结拦截、容量拦截、同货位拦截和 Mapper XML 绑定。

`InventoryMovementMysqlIT` 是本机 Docker MySQL 回滚测试入口。Docker 引擎启动后设置已有本机环境变量并运行：

```powershell
mvn -pl yudao-module-pharmacy -am "-Dtest=InventoryMovementMysqlIT" "-Dsurefire.failIfNoSpecifiedTests=false" test
```

测试只接受 `127.0.0.1:3307/firstsun_pharmacy`，所有夹具在事务末尾回滚。
