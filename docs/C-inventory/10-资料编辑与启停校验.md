## HTTP 接口

管理端前缀仍为 `/admin-api`。成功 CommonResult 的 data=true。

### PUT /pharmacy/inventory/warehouse/update

权限：`pharmacy:inventory-warehouse:update`。body 示例：

```json
{
  "id": 123,
  "expected": {"whCode":"C01","whName":"常温仓","tempZone":0,"status":1},
  "value": {"whCode":"C01","whName":"一号常温仓","tempZone":0,"status":1}
}
```

expected/value 均必填并执行同样验证：编码 1..16 非空白字符、名称 1..64 非空白字符、温区 0..3、状态 0/1。不能修改 storeId、tenantId 或 isDefault。

- 按真实登录员工门店和租户锁定仓库。不存在/删除/越范围统一 NOT_FOUND。
- 名称、编码修改允许已有库存；编码最终仍由数据库唯一约束裁决，重复立即抛错并回滚。
- 温区变化或启停变化需无未完成作业；温区变化或停用还要求批次账和货位账均没有非零在库/冻结数。qtySold 不作为库存占用。
- 默认仓（或非法 default 标志）的启停拒绝，不能通过“启用另一默认仓”绕过尚未批准的默认仓并发约束。默认仓名称/编码可以修改。
- 停用仓库不级联停用货位；后续操作必须检查父仓状态。

### PUT /pharmacy/inventory/location/update

权限：`pharmacy:inventory-location:update`。body 示例：

```json
{
  "id": 456,
  "warehouseId": 123,
  "expected": {"locationCode":"A01","locationType":0,"maxCapacity":null,"status":1},
  "value": {"locationCode":"A01","locationType":0,"maxCapacity":100,"status":1}
}
```

- id/warehouseId 必填正数；编码 1..32 非空白字符，类型 0..4，容量 null 或 0..4294967295，状态 0/1。
- 先锁本门店仓库，再锁该仓库货位。请求中的 warehouseId 仅定位父仓，不能转移货位归属。
- 父仓停用不允许编辑货位。旧快照不符拒绝，不覆盖。
- 类型、容量或状态变更需无未完成作业。汇总所有未删除货位库存的 qty，包含冻结量；负数、冻结超过数量、批次缺失/删除/药品或归属错误均拒绝。
- 类型变化或停用必须零占用。新容量不能低于占用总量；null 是不限制，0 是零容量。
- 编码修改不改库存或历史来源引用。删除接口仍未开放，历史记录保留。

## 作业门禁与事务

本阶段采用保守的整仓门禁：该仓或全门店未调整完成的盘点单（status!=3）、未执行/未取消且明细关联该仓的报损单、该仓关联尚未释放/出库转化的库存锁，都会阻止相关结构/状态/容量修改。锁过了 expire_at 也不自动当作已释放；C 不替 F 改生命周期。

这些检查只读取既有 C 库存作业表和 ph_inv_lock，不修改锁或其他成员业务表。B/D/F 未完成单据的共用锁顺序、以及新增作业必须先锁仓库的契约仍须确认；本轮测试不证明其他成员已遵守此约定。

编辑服务使用本地 READ_COMMITTED 事务，先获得仓库锁，再执行占用和作业查询。这保证等待前一位仓库写入者提交后，后续查询不沿用等待前的旧快照。Spring 若加入不兼容的外层事务，服务会在执行范围查询/SQL 前拒绝；不悄悄以 REPEATABLE_READ 等隔离级别继续。更新须影响一条记录，异常行数、唯一冲突和其他异常均向外抛出，事务回滚。

该接口是管理资料命令，不是供 B/D 调用的库存交易接口。没有变更库存数量、库存流水、来源状态；没有默认仓切换或未经批准的迁移。
