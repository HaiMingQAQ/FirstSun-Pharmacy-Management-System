# C/P2 线上订单冻结接口

日期：2026-09-16。基线：main 已合入 F 的线上订单代码。

## 门面方法

InventoryFacade 新增：

| 方法 | 用途 | 流水 |
| --- | --- | --- |
| reserve(storeId, ReserveItem) | 下单冻结；未指定批次/货位时按 FEFO 分配 | 80，frozen_delta 为正 |
| release(storeId, ReleaseItem) | 取消或超时释放原冻结 | 81，frozen_delta 为负 |
| consumeReservation(storeId, ConsumeItem) | 支付后冻结转出库 | 82，out_qty 为正、frozen_delta 为负 |
| getAvailableQty(storeId, drugIds) | 下单前读取可售量 | 不写入 |

冻结：批次 qty_avail 减少、qty_frozen 增加；货位 qty 不变、qty_frozen 增加。

释放反向处理。冻结转出库减少 qty_total 与 qty_frozen，qty_avail 保持不变，qty_sold 增加。这样始终满足：

    qty_total = qty_avail + qty_frozen

不要在冻结转出库时再次减少 qty_avail。

## 调用数据

ReserveItem 必填 drugId、qty、bizNo、bizLineId；batchId 与 locationId 同时传或同时不传。

release / consumeReservation 的每个明细必填：

- 新操作的 bizNo、bizLineId：幂等键。取消或超时应使用独立业务号，例如 WXC-订单号。
- 原冻结的 originalBizNo、originalBizLineId。
- 原冻结返回的 batchId、locationId、drugId、qty。

reserve 返回的实际批次/货位分配必须由 F 落库，后续释放和转出库按该分配逐条调用。

冻结、释放、转出库使用 biz_type=6。相同业务号、行号、批次、货位可分别拥有 80、81、82 三种流水，重试不会重复执行。部分流水或原冻结已被释放/转出超额时，后端拒绝。

支付完成后退款/退货仍调用 returnBack。C 已兼容把 82 视为原出库流水，与普通销售 20 使用同一原批次、原货位累计回补限制。

## 权限和事务

接口保留当前 InventoryReadAccess 门禁：调用时必须有目标门店在职管理员的租户上下文。F 的管理端订单节点可以直接调用；小程序回调、无人定时任务若没有该上下文，需要 F 与集成负责人提供受控的服务身份，不能绕过库存门店隔离。

每个方法均为本地事务。库存数量、冻结量、流水、F 来源业务状态应由 F 调用点放在同一事务中提交。
