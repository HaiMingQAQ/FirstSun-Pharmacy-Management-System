# FirstSun 药店管理系统前端界面统一规范

本规范适用于 A～F 六名成员开发的管理端页面。小程序继续遵循 `mall-uniapp` 现有设计体系，由 F 维护；涉及管理端与小程序的共同业务术语时保持一致。

## 1. 统一原则

- 以当前 `admin-ui` 的 yudao 页面和 Element Plus 组件为设计基础。
- A 先完成一个“药品分类”标准页面，其他成员以该页面作为药店管理模块的视觉和交互参考。
- 优先复制现有同类页面的结构并替换业务内容，不为个人模块重新设计导航、配色和组件体系。
- 复用项目已有组件、主题变量、图标、表单校验、分页和权限指令。
- 禁止在业务页面修改全局样式；确需公共样式时，由 A 统一评审和合并。

## 2. 页面结构

标准列表页按以下顺序组织：

1. 查询区域：常用条件直接显示，低频条件放入展开区域。
2. 操作区域：新增、导出等主要操作在左侧；刷新、列设置等辅助操作遵循现有框架。
3. 数据表格：操作列固定在右侧，常用识别字段靠左。
4. 分页区域：使用项目现有分页组件和默认位置。
5. 编辑区域：简单信息使用弹窗，字段较多时使用抽屉或独立详情页。

不要在同类页面中混用完全不同的卡片、按钮位置和表格操作方式。

## 3. 组件与交互

| 场景 | 统一约定 |
| --- | --- |
| 主操作 | 使用 Element Plus `primary` 按钮，并遵循现有权限指令 |
| 删除等危险操作 | 使用 `danger` 语义并二次确认 |
| 行内操作 | 顺序统一为查看、编辑、业务操作、删除；操作过多时收入“更多” |
| 状态显示 | 使用项目现有字典和标签组件，不手写互不一致的颜色 |
| 表单 | 标签位置、宽度、必填标识和校验提示参考标准页面 |
| 加载 | 请求期间显示 loading，禁止重复提交 |
| 空数据 | 使用项目现有空状态，不用临时文字或图片代替 |
| 成功与失败 | 使用项目统一消息组件；后端错误不得静默吞掉 |
| 日期时间 | 列表保持同一格式，优先使用项目已有格式化函数 |
| 金额 | 药店业务显示人民币元并保留两位小数；支付接口边界明确元/分转换 |

## 4. 布局与样式

- 默认使用框架已有页面容器，不另加大面积背景色、渐变或阴影。
- 间距优先复用现有工具类和组件间距。确需局部样式时，统一以 `8px` 的倍数组织常用间距。
- 表格、查询表单、弹窗和按钮尺寸采用现有项目默认值。
- 颜色使用框架主题色和 Element Plus 语义色，不直接散落新的十六进制品牌色。
- 局部样式使用 `scoped`，类名表达业务含义；禁止使用大范围 `!important` 覆盖框架。
- 页面至少适配团队约定的演示分辨率；窄屏时查询项可以换行，主要按钮和表格操作不能重叠。

## 5. 业务术语

以下名称在菜单、页面、接口说明和文档中保持一致：

```text
门店
员工
药品分类
药品档案
药品条码
供应商
采购订单
采购收货
批次库存
库存流水
销售订单
销售退货
处方审核
会员
积分
```

同一对象不要在不同页面混用“商品/产品/药物”等多个名称。确需区分“商品”和“药品”时，应先在跨模块接口契约中定义含义。

## 6. 前端文件边界

管理端药店业务代码统一放置在：

```text
admin-ui/src/views/pharmacy
admin-ui/src/api/pharmacy
```

各成员使用自己的业务子目录：

```text
A：pharmacy/base
B：pharmacy/purchase
C：pharmacy/inventory
D：pharmacy/pos
E：pharmacy/prescription、pharmacy/pay
F：pharmacy/member
```

如果仓库实际 API 目录层级不同，应保持现有结构并在 PR 中说明，不能同时保留两种目录方案。

以下内容由 A 统一协调：

- `pharmacy` 公共组件和公共样式
- 全局主题、布局和路由基础配置
- 菜单层级与菜单图标
- 通用枚举、字典和跨模块 TypeScript 类型
- 依赖升级及新的前端依赖

## 7. 页面交付检查

每个页面提交 PR 前确认：

- [ ] 页面结构与 A 提供的标准页面一致。
- [ ] 使用真实接口，没有把 Mock 数据作为完成结果。
- [ ] 查询、重置、新增、修改、状态操作和分页行为一致。
- [ ] 权限不足时按钮和接口均受限制。
- [ ] 加载、空数据、校验失败、接口失败均有正常反馈。
- [ ] 删除、退款、出入库等重要操作有确认和防重复提交。
- [ ] 没有修改全局样式或引入新的 UI 框架。
- [ ] 页面在团队演示分辨率下无明显错位、遮挡或横向溢出。
- [ ] PR 附带至少一张页面截图，便于审核视觉一致性。

## 8. 视觉评审方式

每位成员完成第一个列表页后，先提交截图进行一次小组评审，再批量开发同模块页面。评审只需核对页面结构、按钮顺序、状态颜色、表单布局和业务术语。通过后以该页面作为本模块后续页面模板。
