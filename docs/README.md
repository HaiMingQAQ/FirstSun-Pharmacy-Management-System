# FirstSun 药店管理系统小组分工

本项目采用基于 ruoyi-vue-pro / yudao-vue-pro 二开的六人全栈开发，成员暂用 A～F 表示，分配时替换为姓名。每人负责页面、后端接口、数据库操作和联调自测。

所有成员共同遵守 [开发规范与 AI 协作规则](./开发规范与AI协作规则.md)。规范是适用于所有成员和 AI 的精简规则；具体模块与表归属见六人分工方案。

## 开工核对项

1. 明确“约 40 张表”是否包括框架表。当前 40 张表没有包含若依/yudao `system`、`infra` 的登录、权限、字典等表；复用框架时总数会增加，不能继续宣称整个系统仅有 40 张表。
2. 核对支付与会员模块依赖。`pay_order.extension_id` 对应的 `pay_order_extension` 未保留，钱包缺少 `pay_wallet_transaction` 等流水与充值结构；不能直接认为完整支付和储值模块可运行。
3. 统一库存字段含义、选批规则和事务边界。资料中 FIFO 与“效期最早优先”混用，建议明确采用效期最早优先；未冻结销售不能照抄同时减可用量、冻结量的示例。库存变化与流水应在本地事务内一致提交。
4. 补齐页面所需字段与现有结构的映射，例如药品图片与说明信息、员工与框架账号的关联。通过必要字段调整解决，不为页面随意新增表。
5. 采购退货、养护温湿度、独立销毁台账、离线同步、优惠券、配送和评价等缺少完整表结构，不作为现有 40 表已支持的功能。扩展前重新评估范围与表数。
6. 第一阶段以现金结算走通流程；真实第三方支付需完成模块适配及环境配置。演示支付必须明确标识，不可当成真实支付完成。
7. 未完成审方时不放行处方药交易；第一阶段可只使用普通 OTC 演示商品。过期、停售和库存不足拦截属于销售基础校验。

## 通用协作规则

- 使用同一个 yudao 后端工程，按药店业务模块协作；不为人数拆成多个微服务。
- 药店业务优先放入 `yudao-module-pharmacy`；管理端页面放入 `yudao-ui-admin-vue3/src/views/pharmacy`；管理端接口放入 `yudao-ui-admin-vue3/src/api/pharmacy`；小程序基于 `yudao-mall-uniapp` 二开。
- 复用 `system`、`infra`、`member`、`pay` 等 yudao 现有模块，不为登录、角色、菜单、字典、会员账号和支付基础结构重复造轮子。
- 每张表和共享服务有一名主要维护人，其他人通过服务使用；数据库变更先说明影响，由集成负责人汇总迁移脚本。
- 每项开发交付包含页面、接口、数据操作、权限校验、自测记录和接口说明。生成 CRUD 后仍需实现业务校验，不能只提交空页面或生成代码。
- 功能分支独立开发，每日合入可运行版本。前期先约定请求字段、返回字段、状态码、金额单位及业务单号。
- 药店业务金额为 DECIMAL 元，现有 pay 表多以整数分存储，支付边界必须统一转换和校验。
- 支付回调、销售提交、收货入账、盘点调整及退货执行均需防重复；外部支付不能靠本地数据库事务回滚，须明确失败和补偿处理。
- 演示及统计只展示已经实现并验证的功能，文档和 PPT 与最终代码一致。
